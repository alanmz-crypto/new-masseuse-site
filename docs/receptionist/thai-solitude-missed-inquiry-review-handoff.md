# [Arc none] Thai Solitude missed-inquiry recovery — adversarial review handoff

> **Reviewed PASS with corrections, 2026-10-05. No implementation authorization.** Read with [receptionist plan v7](thai-solitude-receptionist-plan.md), whose implementation remains on ice. This handoff proposes a way to choose a solution; it does not select a vendor, change the phone line, publish copy, or reopen chat.

## Decision to improve

Butsaba wants coverage because she cannot answer clients while giving a massage. The 2026-10-05 desk test found a `tel:` and `mailto:` path on live Contact, an `sms:` path on staging12 Contact, and no visible booking link on eight inspected routes of either site. It did not establish what happens to an unanswered call or whether a client receives an acknowledgment. The plan currently names callback, self-booking, and live answering as separate candidates. None has been shown to solve the observed missed-inquiry problem.

**Design hypothesis:** treat the first release as *missed-inquiry recovery*, with one primary response path and a fallback chosen from observed client tasks. A FAQ may support routine facts, but it is not the recovery path for a caller who has already dialed. The first thing to test is the existing phone route, because live Contact already invites calls while no booking link is visible. This is a test priority, not a decision to use voicemail or callback.

## Proposed discovery and decision protocol

1. **Establish permission and context.** Butsaba confirms whether she is taking private clients, which phone number and channels she owns for them, and whether calls actually arrive during sessions. Ryan reviews the actual employment agreement before any client-facing site or phone change. If private-client traffic has not started, use hypothetical scenarios to test mechanics but leave demand and frequency marked unknown.
2. **Count attempts, including silent losses where observable.** For roughly two working weeks, record aggregate counts of calls, texts, email, and site inquiries received while she is unavailable. For each missed call, record whether caller ID was shown; for shown numbers, count returned versus not returned. Separately count voicemail left versus no voicemail, without adding those overlapping categories together. Use the existing call log to return recoverable missed calls, but put only counts and outcomes in the planning record, never the numbers. Record broad task, time sensitivity, and resolution *when known*; mark the task unknown when a caller leaves no message, even if caller ID is available. No names, phone numbers, message text, or health details enter the planning record. Do not infer that voicemail count equals missed-call count. If the existing log cannot show unanswered attempts, record that blind spot rather than estimating them from voicemails.
3. **Trace the current phone and text paths under normal session conditions.** With Butsaba's approval, use a number not saved in her contacts during a real or realistic massage session while her phone has its normal Focus, screening, and notification settings. Make one non-sensitive call that leaves a message, one that hangs up without a message, and one test text from an unknown number. Observe ringing or filtering, voicemail behavior, caller acknowledgment, message/text delivery, and whether Butsaba notices each afterward. If voicemail is already full or unset, observe that behavior; otherwise schedule a separately approved controlled test with state capture and restoration. Until that condition is checked, mark callback delivery unverified. Record the path and timestamps without retaining caller identifiers. Do not alter production phone settings as part of this discovery test.
4. **Have Butsaba rank real tasks.** Review counts and five non-identifying scenarios: routine fact, appointment request, callback-tolerant question, immediate-answer request, and health-suitability question. For each, ask what the client needs *before she is free* and what she can realistically promise. Consider consequence and time sensitivity as well as frequency; a frequent low-stakes question does not erase a less frequent task that needs live handling.
5. **Write stop conditions before reviewing the counts, then choose one primary candidate with a named fallback.** Callback includes returning missed calls from caller ID as well as voicemail; stop it as the main solution if most missed tasks need an answer before Butsaba is free, or if the phone test reveals silent losses it cannot recover. Self-booking stops if no platform is approved or a representative booking and cancellation cannot complete without her. Live answering stops if session-time missed-call volume falls below a threshold Ryan records before seeing the count; if it remains viable, require a named human, coverage hours, approved answers, personal-judgment escalation, and reviewed cost. An automatic missed-call text with a booking link is a fourth candidate only if the phone can reliably send and receive texts, the platform exists, and its new data flow and wording pass review. A mixture is allowed if the task mix warrants it, but each channel needs a clear owner and visitor promise. Chat remains unplanned.
6. **Rehearse before release.** Walk through the representative cases on the proposed route, including unknown-number unanswered call, no voicemail, test text, booking, and health-suitability handoff. The visitor must reach an accurate next step without an invented booking confirmation or an unsupported callback promise. Ryan independently reviews any voicemail greeting or automatic text as client-facing regulated copy; whether license-display rules apply to a voicemail greeting stays an open legal question. The rehearsal is not a substitute for a later limited real-world pilot and release approval.

## Evidence that could raise confidence

The design choice should not be called high confidence until the phone path is observed, Butsaba confirms which tasks matter and what she can deliver, the primary candidate handles those tasks in a non-sensitive rehearsal, and any new channel has its data-flow and legal review. A limited pilot would then measure contact capture, correct next step, callback-window adherence or booking completion, interruptions to sessions, and Butsaba's workload. Counts should be reported with denominators and dates; a handful of successful synthetic calls cannot establish client acceptance.

If the two-week count is absent or too small to distinguish candidates, keep the solution on ice. A mechanics test may still reveal a broken voicemail or message route, but it cannot prove which receptionist service clients want. Do not substitute a longer plan or more model testing for this missing evidence.

**Confidence remains provisional:** before the review, Codex estimated 80% for the selection protocol and 40% callback, 25% self-booking, 35% live answering, and 30% FAQ as the primary solution. The reviewer estimated 75%, 50%, 25%, 20%, and 20% respectively. Corrections improve the test design but add no observed client evidence, so neither set is an observed success rate or a reason to select a solution.

## Review outcome and stop point

The independent reviewer gave this discovery-and-selection design **PASS with corrections**. This revision covers unknown-number calling in normal session mode, an unknown-number text, caller-ID recovery, voicemail full/unset behavior, the staging12 email-to-SMS data-flow change, and predeclared stop conditions. The PASS authorizes no phone, site, provider, or database change.

Further design is at diminishing returns. The next information-bearing steps are Butsaba's private-client status, client-line type and text capability, realistic callback time, and two weeks of coarse inquiry counts; Ryan reviews the actual employment agreement and confirms the release-candidate staging site. With Butsaba's approval, one unknown-number call and one unknown-number text during normal session phone mode can test mechanics. If voicemail full/unset behavior requires changing the live line, that is a separate controlled test decision. Keep implementation on ice until these facts are recorded.
